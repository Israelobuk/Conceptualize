# Conceptualize V0.7 — Context Engine Economics

## Result

V0.7 did **not** demonstrate that Conceptualize preserves task correctness while materially reducing provider-reported model input. The full-context baseline passed 2/3 runs, meeting the minimum validity gate but not the preferred 3/3. Precompiled Conceptualize context passed 0/3. Its provider input was 20.45% lower than the full-context mean, short of the predeclared 25% threshold and without preserving the frozen rubric result.

This is one synthetic long-conversation task and one model/configuration. It is evidence about this fixture, not a general quality or performance claim.

## Frozen task and grading

The fixture is `v0.7-context-economics-atlas-9`, with 119 messages and 8,223 cl100k tokens of serialized history. It includes initial and changed architecture decisions, explicit supersession metadata, current constraints and implementation state, repeated discussion, unrelated project notes, quoted stale proposals, and conversational acknowledgements. All final A/B runs used the exact same final question and common answer instructions.

The frozen truth SHA-256 is `6ad07d7609cb249b4f5178cda69fa6471c8d1c8db9097572c36a460d726621be`; fixture SHA-256 is `2e3c86cc1c0f9ad5105ce752e6355da56d423f3f1836f228b3f0a4fe0ce71e9f`. The threshold was set before the counted v9 runs: every critical proposition, at least 90% total fact coverage, correct next step, and no stale proposal asserted as current. There are 23 graded propositions, 20 marked critical.

Rubric calibration found that early deterministic phrase alternatives rejected clear paraphrases and facts placed under a different requested heading. Versions 1–8 and their results are preserved under [`evaluations/v07/attempts`](v07/attempts/); only v9 is counted below. The factual propositions, criticality, and pass threshold stayed unchanged; accepted representations and fact placement handling were corrected before the v9 runs. After B, the frozen rubric was not changed.

There is a remaining grading limitation. A post-run audit found that the selected context includes `v07-118` stating “record persistence and metadata sync are integrated,” while the frozen alternative for the metadata-state proposition does not recognize that wording. The raw frozen grade is retained without adjustment. This can undercount context/answer fact coverage; it does not turn any B run into a pass or support an economics claim.

## Context-engine evidence and diagnosis

The final 4,000-token pack considered 91 candidate units (5,784 candidate tokens), selected 48 units (3,477 context-string tokens), and omitted 43. It suppressed three explicitly superseded units (107 tokens), 2,247 low-relevance tokens, zero exact/near-duplicate tokens, and zero unchanged tokens. Budget utilization was 86.92%. Local deterministic pack time was about 198 ms in the isolated runtime measurement: 66.7 ms scoring and 130.9 ms compilation. Git analysis was not applicable to this conversation-only source.

The first B result exposed a real top-k retrieval defect: the broad planning query capped candidate selection before pack scoring, omitting later current decisions despite unused budget. The runtime now expands the candidate pool for broad planning queries to the available conversation messages, while the requested token budget still limits delivery. A regression test proves a decision after the old top-k is considered. A second regression adds deterministic priority for explicit “implemented/integrated/shipped/unfinished” state statements. These are general rules; no fixture IDs or answer phrases are embedded in runtime code.

Those fixes raised selected context from 1,824 to 3,477 tokens and surfaced more current-state messages, but B remained 0/3. Provider input reduction also moved below the 25% target. Because B did not preserve correctness, the budget sweep was **not run**. Increasing or decreasing the budget before resolving the remaining quality gap would violate the benchmark protocol.

## MCP and host diagnostics

The actual product MCP stdio server initialized and advertised only `conceptualize_context`; no API call or browser was needed for this list-tools smoke. The serialized local schema was 764 bytes / 161 cl100k tokens. The V0.5 six-tool estimate remains 1,466 local tokens; V0.6 default remains 277 local tokens. These are local serialization estimates, not provider input.

The full-history host control enabled a dedicated inert read-only MCP tool and did not invoke it. It recorded 28,404 provider input tokens, 19,072 cached, 790 output, and 34,755 ms in one run. Against the three-run A mean, input was 5,601 tokens (24.56%) higher. The inert schema was only 59 local cl100k tokens. This points to MCP-enabled Codex host/config overhead, but provider telemetry cannot identify the specific internal component; this is one diagnostic run, not a stable effect estimate.

One autonomous Mode C attempt used the same task but the MCP call did not execute: Codex returned “MCP tool call requires approval, but approval policy is never.” No context was returned. That failed attempt recorded 40,718 provider input tokens, 32,512 cached, 288 output, and 21,389 ms; it is not a valid autonomous correctness or economics run. A proposed runner change using `--approve-for-me` was rejected by automatic approval review because that flag routes approval through a workspace-write sandbox. No workaround was attempted. The blocked attempt is preserved in [`v07-mode-c-approval-blocked.json`](results/v07-mode-c-approval-blocked.json). The exact host component remains unobservable. Historical V0.6 autonomous and no-adoption results are preserved separately and are not pooled with V0.7.

## Cost, validation, and reproducibility

Cost is unavailable because no verified model pricing snapshot/version was available. Provider token telemetry is the primary model-context measurement; context-string tokens, MCP schema estimates, and runtime timings are reported separately.

Validation on 2026-09-28: Python tests **100 passed** (one Starlette/httpx deprecation warning); Ruff `ruff check apps packages tests` **passed**; `compileall -q apps packages tests` **passed**; frontend tests **4 passed, 0 failed**; TypeScript typecheck **passed**; production Next.js build **passed**. The production MCP stdio initialize/list-tools smoke **passed** and advertised exactly one default tool, `conceptualize_context`. The test suite includes the unified context, repository and conversation retrieval, session ledger, redundancy, supersession, source freshness, and V0.7 deterministic benchmark regressions. No browser smoke was run, consistent with this evidence-focused phase and without opening a test browser.

Reproduce the final precompiled run from the repository root with:

```powershell
.\.venv\Scripts\python.exe -m conceptualize_evaluation.v07_fixture
.\.venv\Scripts\python.exe -m conceptualize_evaluation.v07_economics --mode A --repetitions 3 --output-root evaluations/runs/v07-reproduction
.\.venv\Scripts\python.exe -m conceptualize_evaluation.v07_economics --mode B --repetitions 3 --budget 4000 --output-root evaluations/runs/v07-reproduction
```

The final decision is **not demonstrated**: Mode A met only the minimum baseline-validity requirement (2/3); Mode B used 20.45% less average provider input but passed 0/3. This task therefore does not show preserved correctness with materially less model input.
